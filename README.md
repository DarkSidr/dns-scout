# DNS Scout для OpenWrt

DNS Scout проверяет DNS-over-HTTPS (DoH) серверы с вашего роутера, показывает их доступность и задержку, помогает выбрать основной DNS и до двух резервных. Управление — через **Службы → DNS Scout** в LuCI, обработка DNS-запросов — через `https-dns-proxy` и `dnsmasq`.

Выбирайте серверы вручную или включите ежедневный подбор по расписанию. Перед применением пакет проверяет выбранную цепочку; при ошибке изменения откатываются.

## Установка и обновление

Выполните на роутере по SSH:

```sh
curl -fL https://raw.githubusercontent.com/DarkSidr/dns-scout/main/install.sh -o /tmp/dns-scout-install.sh && sh /tmp/dns-scout-install.sh
```

Если `curl` не установлен:

```sh
wget -O /tmp/dns-scout-install.sh https://raw.githubusercontent.com/DarkSidr/dns-scout/main/install.sh && sh /tmp/dns-scout-install.sh
```

Установщик определяет архитектуру и пакетный менеджер APK/OPKG, скачивает последний релиз и проверяет контрольные суммы. Эта же команда обновляет пакет с сохранением настроек. Если отсутствуют индексы зависимостей, повторите запуск с `--update-index`.

Откройте **Службы → DNS Scout**. Если пункт не появился, обновите страницу LuCI. Прямой путь: `/cgi-bin/luci/admin/services/dns-scout`.

### Другие способы установки

```sh
# Конкретная версия
sh /tmp/dns-scout-install.sh --version 0.2.0-r3

# Скачать и проверить пакет без установки
sh /tmp/dns-scout-install.sh --dry-run

# Локальный каталог с release.json, SHA256SUMS и пакетом
sh /tmp/dns-scout-install.sh --local-dir /tmp/dns-scout-release
```

Для ручной установки скачайте из [релизов](https://github.com/DarkSidr/dns-scout/releases) пакет под точную архитектуру OpenWrt. Например, для `aarch64_cortex-a53`:

```sh
# APK
apk add --allow-untrusted /tmp/luci-app-dns-scout-0.2.0-r3.aarch64_cortex-a53.apk

# OPKG
opkg install /tmp/luci-app-dns-scout_0.2.0-r3_aarch64_cortex-a53.ipk
```

`--allow-untrusted` требуется для APK без подписи репозитория. Зависимости: `luci-base`, `rpcd`, `ca-bundle`, `https-dns-proxy`; также используются штатные `uci`, `ubus`, `dnsmasq` и `cron`.

## Быстрый старт

1. Откройте **Службы → DNS Scout**.
2. Для первого теста оставьте **3 запроса**, **таймаут 5 секунд**, **1 параллельную проверку**.
3. Если меняли параметры или каталог, нажмите **Сохранить настройки**.
4. Нажмите **Запустить тест** и дождитесь завершения.
5. Нажмите **Применить лучший + резерв** и подтвердите. Для своего основного DNS используйте **Применить** в его строке.
6. Дождитесь сообщения **Готово**. В строке **Последнее подтверждённое применение** появятся время и выбранная цепочка.

**Сохранение настроек и ручной тест не переключают DNS.** Для смены рабочих серверов нужно применить результат или включить автовыбор по расписанию.

| Кнопка | Что делает |
| --- | --- |
| **Сохранить настройки** | Сохраняет параметры теста, каталог, расписание и резервирование. |
| **Сохранить резервирование** | Сохраняет только режим и выбор резервов. |
| **Запустить тест** | Проверяет сохранённый каталог и обновляет результаты. |
| **Применить** в строке | Делает этот сервер основным и применяет сохранённые настройки резервов. |
| **Применить лучший + резерв** | Выбирает основной по рейтингу и применяет сохранённые настройки резервов. |

## Основной DNS и резервы

### Свой основной DNS и свои резервы

Например, чтобы получить **Digitale Gesellschaft → Quad9 → OpenDNS**:

1. В каталоге включите для этих серверов **Тестировать** и **Разрешить выбор**, сохраните настройки и запустите тест.
2. В блоке **Резервные DNS** установите **Выбрать вручную**.
3. Выберите Quad9 первым резервом, OpenDNS — вторым.
4. Нажмите **Сохранить резервирование**.
5. В таблице результатов нажмите **Применить** в строке Digitale Gesellschaft и подтвердите цепочку.

Второй резерв необязателен. Значение **Не использовать** позволяет оставить один резерв или работать без резервов.

Все выбранные серверы должны пройти **100% проб** в завершённом тесте **не старше часа**. Основной не должен совпадать с резервным по URL. Если закреплённый резерв не прошёл тест, вся цепочка не применяется: выберите другой резерв или повторите проверку.

### Автоматический выбор резервов

Выберите **Автоматически по рейтингу** и задайте **Всего DNS в цепочке**:

| Значение | Состав |
| --- | --- |
| `1` | Только основной DNS |
| `2` | Основной и один резерв — по умолчанию |
| `3` | Основной и два резерва |

Сохраните резервирование и примените результат. Резервы выбираются среди разрешённых серверов со всеми успешными пробами. Известные адреса одного провайдера исключаются как независимые резервы. Если подходящих серверов меньше, цепочка будет короче.

### Когда используется резерв

Переключением управляет `dnsmasq`: серверы используются в заданном порядке с `strictorder`. При недоступности основного запросы могут идти через резерв. Ожидание зависит от характера сбоя; поле **Таймаут** в DNS Scout управляет только тестированием.

Ответ «домен не существует» или ответ с фильтрацией не означает недоступность DNS и не служит поводом искать другой ответ у резервного провайдера.

## Подбор по расписанию

1. В поле **Ежедневный тест** задайте время, например `17:30`.
2. Для автоматической смены основного DNS включите **Автовыбор после теста по расписанию**. Без галочки тест только обновляет результаты.
3. Нажмите **Сохранить настройки**.

Cron запускает проверку раз в сутки по **времени и часовому поясу роутера**. Чтобы выключить расписание, очистите поле времени и сохраните настройки.

При ручных резервах автовыбор меняет основной DNS, сохраняя выбранные вами резервы. Если подходящего основного нет или закреплённый резерв не прошёл проверку, рабочая цепочка остаётся прежней. Если выбранная цепочка уже настроена и исправна, лишний перезапуск не выполняется.

Проверка расписания:

```sh
date
crontab -l | grep dns-scout
```

Для `17:30` ожидается:

```text
30 17 * * * /usr/sbin/dns-scout scheduled # dns-scout
```

Ручная кнопка **Запустить тест** всегда выполняет только тест, даже при включённом автовыборе. Расписание не является непрерывным мониторингом доступности.

## Настройки тестирования

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| **Bootstrap DNS** | `77.88.8.8, 9.9.9.9, 1.1.1.1` | От 1 до 8 публичных IPv4 через запятую для поиска IP DoH-сервера. |
| **Тестовые домены** | `example.com, openwrt.org, iana.org` | От 2 до 8 существующих доменов с публичной A-записью, без `https://` и пути. |
| **Запросов на сервер** | `3` | От 2 до 10 проб всего на сервер. Домены перебираются по кругу. |
| **Таймаут, секунд** | `5` | От 2 до 15 секунд на пробу, включая bootstrap и HTTPS-подключение. |
| **Параллельных проверок** | `1` | От 1 до 8 серверов одновременно. Большее значение ускоряет тест и повышает нагрузку. |

Для слабого роутера оставьте параллельность `1` и небольшой список. Для более подробной проверки увеличьте число запросов до `5–10`. Чтобы охватить все тестовые домены на каждом сервере, число запросов должно быть не меньше числа доменов.

### Bootstrap DNS

Для подключения к DoH по имени сначала нужен его IP-адрес. DNS Scout обращается к bootstrap-серверам в указанном порядке. Для DoH URL с IP-адресом этот поиск не нужен.

Bootstrap использует обычный незашифрованный DNS. Он нужен для начального подключения и не заменяет DoH-резервы для запросов устройств. При применении сохранённый список передаётся в `https-dns-proxy`.

Таблица **Bootstrap DNS** показывает результаты отдельных проверок этих адресов. Чтобы поменять их порядок или удалить недоступный адрес, отредактируйте поле в настройках и сохраните его.

## Каталог серверов

### Добавить свой сервер

1. В **Каталоге серверов** нажмите **Добавить сервер**.
2. Укажите название и полный DoH URL провайдера, например `https://dns.example.net/dns-query`.
3. Включите **Тестировать**. Чтобы использовать сервер как основной или резервный DNS, включите также **Разрешить выбор**.
4. Нажмите **Сохранить настройки**, затем **Запустить тест**.

| Флаг | Назначение |
| --- | --- |
| **Тестировать** | Включает адрес в следующий тест. |
| **Разрешить выбор** | Допускает ручное и автоматическое применение, а также выбор в качестве резерва. |

### Дополнительные адреса из gist

В каталоге есть дополнительные адреса из [исторического списка DoH](https://gist.github.com/thiagozs/088fd8f8129ca06df524f6711116ee8f). Они по умолчанию выключены. Подпись **«gist, не проверен»** — часть названия импортированной записи, а не текущий результат проверки. Она остаётся даже после успешного теста. Доступность с вашего роутера смотрите в столбце **Успех** и по времени завершения теста.

Для массового выбора используйте кнопки:

| Кнопка | Действие |
| --- | --- |
| **Тестировать все** | Включает тестирование всего каталога. |
| **Разрешить выбор всем** | Разрешает применение всех записей; флаг тестирования не меняется. |
| **Тестировать и разрешить всех** | Включает оба флага у всех серверов одной кнопкой. |
| **Выключить дополнительные из gist** | Снимает тестирование у дополнительных записей. |

После этого нажмите **Сохранить настройки**, затем **Запустить тест**. Даже при массовом разрешении применяются только серверы со всеми успешными пробами. Проверка большого списка занимает больше времени.

Удаление записи из каталога не меняет уже работающую цепочку. Чтобы заменить действующий DNS, примените другой набор серверов.

## Результаты теста

| Столбец | Как читать |
| --- | --- |
| **Успех** | Корректные ответы / все пробы. `3/3` — сервер прошёл тест; `1/3` — две пробы завершились ошибкой. |
| **Медиана** | Типичная задержка успешных проб. |
| **p95** | Задержка медленных успешных проб. При 2–10 пробах фактически равна максимальной. |
| **Результат / последняя ошибка** | `OK` либо причина последнего сбоя в этом тесте. |

Рейтинг учитывает сначала долю успешных ответов, затем p95. Для применения подходят только серверы без неудачных проб.

Каждая проба создаёт новое HTTPS-соединение и проверяет DNS-ответ. Поэтому задержка включает начальное подключение и может быть выше, чем у уже работающего прокси. VPN и маршрутизация роутера влияют на результаты. Скорость не характеризует политику фильтрации провайдера.

Результаты хранятся в оперативной памяти и исчезают после перезагрузки. **Применённая цепочка DNS, настройки и расписание сохраняются.**

## Применение и восстановление

Перед изменением настроек DNS Scout проверяет кандидатов через установленный `https-dns-proxy`. Затем сохраняет исходную конфигурацию, создаёт до трёх локальных прокси на портах `5053–5055` и направляет к ним запросы `dnsmasq`. Правила DNS для отдельных доменов сохраняются.

После перезапуска проверяются конфигурация, процессы, ответы каждого прокси и `dnsmasq`. Успешный результат отображается в строке **Последнее подтверждённое применение**. Это время завершённой проверки; последующая доступность серверов может меняться.

При ошибке пакет возвращает исходную конфигурацию. Если операция была прервана, восстановление выполняется при загрузке роутера или кнопкой **Восстановить настройки**.

Для применения нужны один экземпляр `dnsmasq` на порту `53`, параметр `https-dns-proxy.config.dnsmasq_config_update='*'` и отсутствие глобального `proxy_server`. Перед применением завершите несохранённые изменения DHCP/DNS и HTTPS DNS Proxy в LuCI.

## Диагностика

### После «Применить» серверы не изменились

Дождитесь завершения операции и прочитайте сообщение сверху страницы. **Сохранить резервирование** только сохраняет выбор; после него нужно нажать **Применить** у основного DNS. Если открыт отдельный экран HTTPS DNS Proxy, обновите его после завершения.

Посмотреть результат операции и сохранённые адреса:

```sh
cat /tmp/dns-scout/job.json
uci show https-dns-proxy | grep -E 'resolver_url|listen_port'
```

### Проверить запуск по расписанию

```sh
crontab -l | grep dns-scout
cat /tmp/dns-scout/job.json
cat /etc/dns-scout/active.json
logread | grep -E 'cron|dns-scout|https-dns-proxy' | tail -n 40
```

После завершения задания ожидаются `kind: "scheduled"`, `running: false` и сообщение `Готово`. В журнале виден запуск cron; `active.json` содержит последнюю подтверждённую цепочку. `job.json` относится к последней операции: последующий ручной тест заменит запись о запуске по расписанию.

### Проверить работу DNS

```sh
ubus call service list '{"name":"https-dns-proxy"}'
uci show dhcp | grep -E '\.server=|\.noresolv=|\.strictorder='
nslookup example.com 127.0.0.1
```

Ожидаются работающие экземпляры прокси, серверы `127.0.0.1#5053` и соответствующие порты резервов, `noresolv='1'`, `strictorder='1'`, а также успешный DNS-ответ. Если установлен `dig`, проверьте каждый настроенный прокси отдельно:

```sh
dig @127.0.0.1 -p 5053 example.com
dig @127.0.0.1 -p 5054 example.com
dig @127.0.0.1 -p 5055 example.com
```

Проверяйте только используемые порты. Ответ от `127.0.0.1:53` сам по себе подтверждает работу локального DNS; отдельные запросы к портам прокси проверяют настроенные DoH-соединения.

### Частые сообщения

| Сообщение или ситуация | Что сделать |
| --- | --- |
| Результаты устарели | Запустите тест заново: срок применения результатов — один час. |
| Резерв не прошёл все тесты | Выберите рабочий резерв или повторите тест. |
| Основной совпадает с резервным | Уберите этот адрес из резервов или выберите другой основной. |
| Сначала сохраните изменения LuCI | Сохраните или отмените ожидающие изменения DHCP/DNS и HTTPS DNS Proxy. |
| Ошибка bootstrap | Проверьте доступность bootstrap-адресов и подключение роутера. |
| Ошибка TLS | Проверьте дату роутера, сертификаты и правильность DoH URL. |
| Таймаут | Повторите тест; при необходимости увеличьте время ожидания или выберите другой сервер. |
| Нужен откат незавершённой операции | Нажмите **Восстановить настройки** или выполните `dns-scout recover`. |

Дополнительные команды:

```sh
dns-scout version             # установленная версия
ubus call dns-scout status    # настройки, результаты и состояние
ubus call dns-scout scan      # запустить тест в фоне
dns-scout preflight          # проверить кандидатов без смены рабочего DNS
dns-scout recover            # завершить откат прерванного применения
```

## Совместимость

На оборудовании проверена **OpenWrt 25.12.4, Banana Pi BPI-R4, aarch64_cortex-a53**. Сборки выпускаются в форматах APK и IPK:

| Платформа | Архитектура OpenWrt |
| --- | --- |
| ARM64 | `aarch64_cortex-a53` |
| ARMv7 | `arm_cortex-a7_neon-vfpv4` |
| MIPS | `mips_24kc` |
| MIPSEL | `mipsel_24kc` |
| x86-64 | `x86_64` |

Другие перечисленные платформы и версии OpenWrt 23.05/24.10 не проходили аппаратную проверку. Для архитектур вне списка нужна [самостоятельная сборка](docs/development.md).

DNS Scout работает с DoH через IPv4; DoT и IPv6-only endpoints не поддерживаются. Постоянно работающего процесса DNS Scout нет: он запускается для теста, применения или задания cron. Для устройств с небольшим объёмом памяти используйте параллельность `1` и короткий каталог. Python, Node.js и Go на роутере не нужны.

## Удаление

### Полное удаление

Выполните от root:

```sh
dns-scout uninstall
```

Команда удаляет пакет, его задание cron, настройки, историю применения, резервные копии и результаты тестов. HTTPS DNS Proxy и рабочая цепочка DNS сохраняются, чтобы роутер продолжал разрешать имена. Остальные задания cron сохраняются.

Если сейчас идёт тест или применение, дождитесь завершения. При незавершённой транзакции сначала выполните `dns-scout recover`. Команда полного удаления доступна с версии **0.2.0-r3**; для старой версии используйте пакетный менеджер или сначала обновите пакет.

### Удаление через пакетный менеджер

```sh
# APK
apk add --no-network https-dns-proxy luci-base rpcd ca-bundle
apk del luci-app-dns-scout

# OPKG
opkg remove luci-app-dns-scout
```
